# StormAuth

Авторизация для Paper/Folia-серверов (1.21+) с авто-входом Bedrock-игроков через Geyser/Floodgate.

## Возможности

- `/register`, `/login`, `/changepassword`, `/logout` (выход со сбросом сессии)
- `/2fasetup` + `/2fa` - двухфакторка через authenticator-приложения (TOTP, rfc 6238);
  обязательна для обладателей права `stormauth.totp.required`
- привязка к соцсетям: `/link telegram` или `/link vk` выдает код, игрок шлет его боту - готово.
  Дальше работают уведомления о входе с нового ip и сброс пароля через `/recovery`
  (код приходит в бота). Оба бота выключаются в конфиге и работают на long-poll -
  наружу ничего открывать не нужно. Для vk нужен ключ сообщества с правом на сообщения
  и включенные сообщения у группы
- уведомления владельцу во все привязанные сети о критических действиях: смена пароля,
  привязка/отвязка, включение и сброс 2fa - владелец сразу узнает,
  если с аккаунтом возится кто-то чужой
- коды привязки и сброса горят после `max-code-attempts` неверных вводов, а бот
  ограничивает число попыток с одного чата - перебор 6-значного кода не прокатит
- капча при регистрации: игрок собирает код из 4 карт на рамках 2x2 и вводит
  `/captcha <код>` (выключается в конфиге, `captcha.enabled`)
- `/stormauth reload | unregister <ник> | changepassword <ник> <новый> | reset2fa <ник> | info <ник> | import authme <файл>` -
  админка, право `stormauth.admin` (по умолчанию op), все команды работают и из консоли
- авто-вход без пароля для лицензионных ников (`premium-autologin`, по умолчанию выключен):
  проверка через api mojang + по умолчанию только с того же ip. Не выключайте
  `require-same-ip` - на оффлайн-сервере ник сам по себе не доказывает владение
  аккаунтом. С включенной 2fa авто-вход не срабатывает, код спросим в любом случае
- аудит безопасности: входы, неудачные пароли, смены паролей, привязки и сбросы пишутся
  в `plugins/StormAuth/security-<дата>.log` (по файлу на день, `security-log.enabled`)
- события для других плагинов: `PlayerAuthedEvent` (игрок полностью вошел) и
  `PlayerLinkedEvent` (аккаунт привязали к соцсети) из пакета `dev.storm.stormauth.api`
- PlaceholderAPI (если стоит): `%stormauth_authed%`, `%stormauth_registered%`,
  `%stormauth_2fa%`, `%stormauth_telegram%`, `%stormauth_vk%` - значения `yes`/`no`
- импорт базы AuthMe (`$SHA$` и открытый текст), легаси-хэши пересчитываются в pbkdf2
  при первом удачном входе
- хэширование паролей считается в async-планировщике: pbkdf2 на 65к итераций не
  морозит игровой поток
- сессии по ip: повторный заход без пароля, пока жив `session-timeout-minutes`
  (проверку ip можно отключить: `session-check-ip: false` - для динамических ip,
  но менее безопасно)
- bedrock-игроки через floodgate заходят без пароля - они уже авторизованы через xbox live
- до входа нельзя двигаться, писать в чат, выполнять команды, драться, трогать инвентарь,
  поднимать и выкидывать предметы (карты и рамки капчи - исключение, иначе капчу не собрать)
- заголовок и bossbar с обратным отсчетом до кика, подсказки в чате остаются
- кик за бездействие до входа (`auth-timeout-seconds`), кик после `max-login-attempts`
  неверных попыток
- временный бан ip после серии киков за неверные пароли (`bruteforce.*`, по умолчанию 15 минут)
- анти-vpn на входе: проверка ip через ip-api или proxycheck, кэш ответов, при недоступном
  api пускаем (настраивается `antivpn.*`, по умолчанию выключено)
- лимит аккаунтов с одного ip (`max-accounts-per-ip`) и черный список слабых паролей
  (`weak-passwords`)
- неверные попытки входа пишутся в консоль с ip игрока
- сообщения на русском и английском, язык выбирается по локали клиента
  (`default-language` - для консоли)
- пароли лежат только как PBKDF2-хэши со случайной солью, в открытом виде нигде не хранятся
- база игроков пишется атомарно (временный файл + замена), рядом остается
  `players.yml.bak` - крах посреди записи не уносит аккаунты
- хранилище аккаунтов на выбор (`storage`): `yaml` (players.yml, по умолчанию), `sqlite`
  (stormauth.db) или `mysql` (секция `mysql` в конфиге). При первом запуске на базе аккаунты
  из players.yml переносятся автоматически, сам файл остается резервной копией; если база
  недоступна, плагин громко ругается в консоль и работает на players.yml
- при обновлении jar новые ключи сами дописываются в существующие `config.yml` и
  `messages_*.yml`, значения и комментарии админа не трогаются

## Сборка

```
mvn package
```

jar лежит в `target/StormAuth-1.7.0.jar`.

## Установка

Закинуть jar в `plugins/`, перезапустить сервер. Для bedrock-поддержки поставить
Geyser + Floodgate - настраивать ничего не нужно, плагин подхватит floodgate сам.
PlaceholderAPI тоже подхватывается сама, если стоит.

Данные игроков - в `plugins/StormAuth/players.yml`, временные баны - в `bans.yml`,
тексты - в `messages_ru.yml` и `messages_en.yml` (перезагружаются через
`/stormauth reload`), аудит - в `security-<дата>.log`.

Folia поддерживается из коробки: задачи идут через AsyncScheduler, глобальный регион
и планировщик сущности, общего bukkit-планировщика код не трогает. Боты соцсетей
крутятся на своих нитях (long-poll) и гаснут на onDisable.

Импорт из AuthMe поддерживает только хэши `$SHA$` и открытый текст - bcrypt/argon2
пропускаются, потому что без исходного пароля их не пересчитать. Если у вас bcrypt -
скажите, добавим поддержку через проверку при входе.
